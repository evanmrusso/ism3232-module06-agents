## My Assistant: Grass Dragon FAQ Assistant

Kc is an FAQ assistant for Grass Dragon, a made-up volleyball equipment store, that answers customer questions about store hours, holiday hours, locations, returns, shipping, and payment. Its store answers come from keyword rules and a fixed dictionary of answers in my_main.py, not a real store database, and it only checks that dictionary if a message contains a question mark. Requests about refunds, damaged items, or a customer's own order are passed to a store employee, because the assistant has no access to any customer's order information and cannot decide whether an item was damaged or give money back. If a message has no matching keyword or no question mark, it goes to a local AI model, and if the model is unavailable, Kc asks the customer to try again. If this assistant used real customer data, its history would store every message exactly as typed, so a customer who sent their card number, address, or order details would have that private information saved in plain text where others could see it.

## Adding a Model to Kc

Kc now uses a local model through Ollama for messages that the rules and store information do not cover. The model answered "Do teams get a discount?" well, saying teams of 6 or more players get a 10 percent discount, which matches the facts in its instructions. When I asked "Do you sell sunscreen?", it said it did not know and told me to ask a store employee, which is better than making up an answer. I kept the store information in code so hours, locations, returns, shipping, and payment answers stay exact every time. I also kept refund, damaged item, and order handoffs in code because Kc cannot see customer orders or make those decisions. In Exercise 4, the local model agreed with a false closing time just because I told it to, so I do not trust it with facts or actions that have real consequences.
